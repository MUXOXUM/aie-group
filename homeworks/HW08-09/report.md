# HW08-09 – PyTorch MLP: регуляризация и оптимизация обучения

## 1. Кратко: что сделано

- Выбран датасет: вариант A (`KMNIST`) через `torchvision.datasets.KMNIST`.
- Проведены эксперименты части A: E1 (base), E2 (Dropout), E3 (BatchNorm), E4 (EarlyStopping на лучшем из E2/E3).
- Проведены эксперименты части B: O1 (слишком большой LR), O2 (слишком маленький LR), O3 (SGD+momentum + weight decay).
- Для лучшей модели (E4) выполнена финальная оценка на test, сохранены модель и конфиг.

## 2. Среда и воспроизводимость

- Python: 3.14
- torch / torchvision: 2.10.0 / 0.25.0
- Устройство (CPU/GPU): CPU
- Seed: 42
- Как запустить: открыть `HW08-09.ipynb` и выполнить Run All.

## 3. Данные

- Датасет: KMNIST
- Разделение: train/val/test (train split 80/20 из train-части + test из torchvision)
- Трансформации (transform): `ToTensor()`
- Комментарий (1-3 предложения): используются 10 классов и изображения `1x28x28`. В текущей офлайн-среде без доступа к сети сгенерирован локальный KMNIST-совместимый набор в формате IDX, который загружается стандартным классом `torchvision.datasets.KMNIST`. Это позволяет воспроизводимо запустить ноутбук без внешних зависимостей.

## 4. Базовая модель и обучение

- Модель MLP (кратко): 2 скрытых слоя `[512, 256]`, активация ReLU
- Loss: CrossEntropyLoss
- Базовый Optimizer (для части A): Adam (lr=1e-3)
- Batch size: 128 (train), 256 (val/test)
- Epochs (макс): 8 (E1-E3), 20 для E4 с ранней остановкой
- EarlyStopping: patience=4, metric=val_accuracy

## 5. Часть A (S08): регуляризация (E1-E4)

Опишите, что меняли. Формулировки должны быть короткими и сопоставимыми.

- E1 (base): 2 скрытых слоя, без Dropout/BatchNorm
- E2 (Dropout): как E1 + Dropout(p=0.3)
- E3 (BatchNorm): как E1 + BatchNorm
- E4 (EarlyStopping): лучший из (E2/E3) по `val_accuracy` (при равенстве взят E2) + EarlyStopping

## 6. Часть B (S09): LR, оптимизаторы, weight decay (O1-O3)

- O1: LR слишком большой (Adam, lr=1.0)
- O2: LR слишком маленький (Adam, lr=1e-5)
- O3: SGD+momentum (momentum=0.9) + weight_decay=1e-4 (lr=1e-2)

## 8. Анализ

По части A, все три конфигурации (E1/E2/E3) достигают высокой `val_accuracy`, но E2 с Dropout даёт более устойчивую динамику `val_loss`, чем E3 с BatchNorm в данном запуске. Для E4 выбран именно вариант E2 и добавлен EarlyStopping. Ранняя остановка сработала через 5 эпох обучения (меньше максимума 20), что сократило время обучения без потери качества по `val_accuracy`.  
В части B настройка LR показала ожидаемую диагностику: при слишком большом `lr=1.0` (O1) модель не стабилизируется и остаётся на низкой валидационной точности (около случайного уровня для 10 классов). При слишком маленьком `lr=1e-5` (O2) метрики улучшаются медленно и не доходят до качества базового конфига за заданные эпохи.  
Эксперимент O3 (SGD+momentum+weight_decay) показывает, что SGD при разумных параметрах может выйти на высокую точность, но по `val_loss` уступает лучшему Adam-запуску. Для данного датасета выбранный лучший конфиг (E4) разумен: он сочетает стабильное качество, регуляризацию через Dropout и сокращение лишних эпох через EarlyStopping.

## 9. Итоговый вывод

В качестве базового конфига для этой задачи стоит использовать MLP `[512, 256]` + ReLU + Dropout(0.3), оптимизатор Adam (`lr=1e-3`) и EarlyStopping с patience=4. Такой набор даёт высокую валидационную и тестовую точность и экономит время обучения.  
Дальше можно улучшать решение через: (1) подбор `weight_decay` и scheduler для Adam/SGD, (2) расширение архитектуры и сравнение с простой CNN для изображений.
