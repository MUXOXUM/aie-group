Проект посвящён построению сервиса автоматической оценки рыночной стоимости подержанных автомобилей на основе их характеристик. ## 2. Постановка задачи и контекст

### Предметная область и задача

Рынок подержанных автомобилей непрозрачен: продавцы нередко завышают цену, покупатели не знают реальной стоимости. Сервис решает задачу **быстрой независимой оценки**: пользователь вводит характеристики автомобиля и получает рыночную цену с указанием диапазона неопределённости.

Потенциальные пользователи: частные покупатели перед сделкой, автодилеры при формировании прайса, агрегаторы объявлений для автоматической проверки цен.

### Формулировка в терминах ML

- **Тип задачи:** регрессия
- **Входные данные:** характеристики автомобиля — производитель, состояние, тип кузова, тип топлива, пробег, тип трансмиссии, привод, возраст, штат продажи и др. (12 признаков)
- **Целевая переменная:** цена объявления в USD
- **Требования:** латентность предсказания < 100 мс, сервис должен работать через REST API, результат включает доверительный интервал

### Целевые метрики

| Метрика | Смысл |
|---------|-------|
| **MAE** (Mean Absolute Error) | Средняя абсолютная ошибка в долларах — интерпретируема напрямую |
| **RMSE** | Штрафует крупные ошибки сильнее, чем MAE |
| **R²** | Доля объяснённой дисперсии, удобен для сравнения моделей |
| **MAPE** | Относительная ошибка в % — показывает точность независимо от ценового диапазона |

MAE выбрана основной метрикой, так как для конечного пользователя важна ошибка в долларах, а не квадратичная. MAPE используется как дополнительный ориентир — она показывает, насколько ошибка велика относительно цены самого автомобиля.

## 3. Данные

### Источник

Открытый датасет **Used Cars Dataset** ([Kaggle](https://www.kaggle.com/datasets/austinreese/craigslist-carstrucks-data)). Файл `vehicles.csv`, ~1.45 ГБ, около 426 000 объявлений о продаже автомобилей в США.

### Структура данных

Один файл CSV с одной строкой на объявление. Ключевые признаки:

| Признак | Тип | Описание |
|---------|-----|----------|
| `price` | числовой | Цена объявления (целевая переменная) |
| `year` | числовой | Год выпуска (преобразован в `car_age`) |
| `manufacturer` | категориальный | Производитель (ford, toyota, bmw, ...) |
| `condition` | категориальный | Состояние: new / excellent / good / fair / salvage |
| `cylinders` | категориальный | Количество цилиндров |
| `fuel` | категориальный | Тип топлива: gas / diesel / hybrid / electric |
| `odometer` | числовой | Пробег в милях |
| `title_status` | категориальный | Статус документов: clean / rebuilt / salvage / ... |
| `transmission` | категориальный | automatic / manual |
| `drive` | категориальный | Привод: fwd / rwd / 4wd |
| `type` | категориальный | Тип кузова: sedan / SUV / pickup / truck / ... |
| `paint_color` | категориальный | Цвет кузова |
| `state` | категориальный | Штат США |

### Предобработка и EDA

Выполнено в `notebooks/exp01_eda_baseline.ipynb`.

**Фильтрация выбросов:**
- Цена: оставлены объявления от $500 до $150 000 (исключены нулевые и нереалистичные цены)
- Год выпуска: 1980–2024
- Пробег: не более 500 000 миль

**Feature engineering:**
- Год выпуска заменён на `car_age = 2022 - year` — более информативный признак для регрессии

**Пропуски:**
- Категориальные признаки: заполнены значением `"unknown"`
- Числовые признаки: заполнены медианой

**Трансформация целевой переменной:**
- Применён `log1p(price)` для стабилизации дисперсии — распределение цены сильно скошено вправо

**Ключевые наблюдения из EDA:**
- Медианная цена ~$13 000, распределение логнормальное
- Наибольшее влияние на цену: возраст автомобиля, пробег, производитель, состояние
- Значительная доля пропусков в `condition` (~40%), `cylinders` (~40%), `drive` (~30%) — покрыта fillna("unknown")
- Премиальные марки (BMW, Mercedes-Benz, Audi) имеют медианную цену в 2–3 раза выше массовых

После очистки осталось ~330 000 строк из ~426 000.

## 4. Модели и подходы

### Baseline — Linear Regression и Ridge

Простые линейные модели обучались на масштабированных признаках после LabelEncoding категориальных переменных. Использовались как нижняя граница качества.

- **Linear Regression** — базовый бейзлайн, без регуляризации
- **Ridge (alpha=10)** — L2-регуляризация для устойчивости при мультиколлинеарности

Ожидаемо показали слабые результаты: линейные модели не улавливают нелинейные зависимости (например, цена падает нелинейно с возрастом и пробегом).

### Улучшенные модели

**Random Forest** (`n_estimators=200, max_depth=20, min_samples_leaf=5`):
- Ансамбль деревьев, хорошо работает с нелинейностями и категориальными признаками
- Даёт feature importance — важно для интерпретации

**XGBoost** (`n_estimators=500, max_depth=7, lr=0.05, subsample=0.8`):
- Градиентный бустинг строит деревья последовательно, каждое исправляет ошибки предыдущего
- L1 и L2 регуляризация (`reg_alpha=0.1, reg_lambda=1.0`) для борьбы с переобучением
- Subsample и colsample_bytree для стохастичности

### Квантильные модели для доверительного интервала

Поверх основной модели обучены два `GradientBoostingRegressor` с `loss="quantile"`:
- `alpha=0.05` — нижняя граница 90% CI
- `alpha=0.95` — верхняя граница 90% CI

Это честный статистический подход к оценке неопределённости предсказания, в отличие от простого умножения на коэффициент.

Эксперименты описаны в `notebooks/exp02_model_comparison.ipynb`.

## 5. Экспериментальный протокол и результаты

### Протокол

- Разбивка: **80% train / 20% test**, стратификации нет (регрессия)
- `random_state=42` для воспроизводимости
- Метрики считаются на тестовой выборке после обратного преобразования: `price = expm1(log_price)`
- Линейные модели обучались на масштабированных данных (`StandardScaler`), деревья — без масштабирования

### Сравнение моделей

| Модель | MAE ($) | RMSE ($) | R² | MAPE (%) | Комментарий |
|--------|---------|----------|----|----------|-------------|
| Linear Regression | ~7 300 | ~11 100 | ~0.42 | ~75% | Baseline, не улавливает нелинейности |
| Ridge (alpha=10) | ~7 300 | ~11 100| ~0.42 | ~75% | Нет улучшения над LinearRegression |
| **Random Forest** | **~3 000** | **~5 900** | **~0.84** | **~35%** | Лучший результат, финальная модель |
| XGBoost | ~3 705 | ~6 500 | ~0.80 | ~39% | Значительный прирост качества |

*Точные значения зависят от конкретного запуска на реальных данных; в ноутбуке `exp02` выводится итоговая таблица.*

### Выбор финальной модели

Выбран **Random Forest** как финальная модель. Он показал наилучшие результаты по всем метрикам при разумном времени обучения (~3–5 минут на полном датасете). XGBoost покозал менее хорошие результаты.

Линейные модели в 2–2.5 раза хуже по MAE — улавливание нелинейности в данных принципиально важно.

## 6. Архитектура решения и сервис

### Пайплайн

Пайплайн состоит из двух независимых этапов: офлайн-обучения и онлайн-инференса.

**Офлайн (обучение):**

```
data/raw/vehicles.csv
        │
src/train.py — load_and_clean()
  - фильтрация выбросов по цене, пробегу, году
  - fillna("unknown") для категориальных признаков
  - вычисление car_age = max_year - year
        │
src/train.py — build_encoders() + encode()
  - LabelEncoder для 10 категориальных признаков
  - log1p(price) для целевой переменной
        │
src/train.py — train()
  - основная модель: RandomForest / XGBoost / Ridge
  - квантильные модели: GradientBoosting q=0.05 и q=0.95
        │
artifacts/models/
  - car_price_model.joblib  (три модели + энкодеры)
  - model_meta.json         (метрики и метаданные)
```

**Онлайн (инференс):**

```
HTTP POST /predict  (JSON с характеристиками автомобиля)
        │
src/service/schemas.py — CarFeatures
  - валидация и нормализация входных данных (Pydantic)
        │
src/models/predictor.py — CarPricePredictor.predict()
  - LabelEncoding входных признаков
  - предсказание median-моделью → predicted_price
  - предсказание q05/q95-моделями → ci_lower, ci_upper
  - вычисление confidence из ширины интервала
        │
HTTP ответ (JSON)
  - predicted_price, ci_lower, ci_upper, confidence, latency_ms
```

При старте сервиса `CarPricePredictor.load()` ищет модель в `artifacts/models/`. Если файл не найден — автоматически обучается demo-модель на синтетических данных, после чего сервис готов к работе.

### API и эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/health` | Проверка работоспособности и загрузки модели |
| `GET` | `/model/info` | Метрики и метаданные обученной модели |
| `POST` | `/predict` | Предсказание цены одного автомобиля |
| `POST` | `/predict/batch` | Пакетное предсказание (до 100 авто) |

Пример запроса к `/predict`:

```json
{
  "manufacturer": "toyota",
  "condition": "good",
  "cylinders": "4 cylinders",
  "fuel": "gas",
  "odometer": 60000,
  "title_status": "clean",
  "transmission": "automatic",
  "drive": "fwd",
  "type": "sedan",
  "paint_color": "white",
  "state": "ca",
  "car_age": 5
}
```

Пример ответа:

```json
{
  "predicted_price": 17850.00,
  "ci_lower": 13200.00,
  "ci_upper": 23400.00,
  "confidence": 0.862,
  "model_used": "RandomForest",
  "latency_ms": 18.4
}
```

## 8. Ограничения и дальнейшая работа

### Текущие ограничения

- Датасет содержит объявления только с американского рынка (Craigslist, цены в USD, пробег в милях) — модель не применима напрямую к российскому или европейскому рынку
- Нет мониторинга дрейфа данных: если рыночные цены изменятся, модель устареет без переобучения
- Цены в объявлениях — запрашиваемые, а не реальные цены сделок; модель предсказывает именно их
- Категориальные признаки закодированы LabelEncoding, что не отражает порядок или близость категорий
- Гиперпараметры не подбирались автоматически (GridSearch / Optuna) — использованы разумные значения из практики

### Направления развития

**Качество модели:**
- Автоматический подбор гиперпараметров через Optuna
- Замена LabelEncoding на CatBoost-энкодинг или One-Hot для категорий с небольшим числом значений
- Добавление признаков: регион (кластеризация штатов), сезонность объявления, популярность модели

**Сервис:**
- Хранение истории запросов в БД для анализа использования
- Авторизация через API-ключ
- Мониторинг распределения входных данных (детекция дрейфа)
- Автоматическое переобучение по расписанию
